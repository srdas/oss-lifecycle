Key Insight on Open Source Economic Asymmetry

Because open-source software is non-rival and non-excludable, standard GDP accounting fails to capture its real wealth creation. While developer labor costs (supply-side) remain bounded in tens of millions of dollars, user cost-savings and velocity enhancements across commercial codebases generate trillions in demand-side surplus.

Research Paper Blueprint

Project Life Cycles in Open-Source Software

Sanjiv Das, Brian Granger, Piyush Jain, David Qiu, Andrii Ieroshenko, Michael Chin — AI/ML Open-Source Team, Amazon Web Services (AWS)

1. Dev Engagement (Bass Diffusion Adaptation)

Adapts product diffusion models (Bass 1969) to repeated monthly developer contributions \(L(t)\). Dev propensity arises from independent utility \(p\) and network imitation/contagion \(q\):

$$\frac{f(t)}{1-F(t)} = p + q \cdot F(t)$$ $$f(t) = \frac{e^{(p+q)t} p (p+q)^2}{[p e^{(p+q)t} + q]^2}$$

2. Endogenous Growth Dynamics (Romer 1990)

Code growth rate \(\dot{A}\) (measured in total line additions & deletions) is modeled using Cobb-Douglas production incorporating "standing on shoulders of giants" vs "fishing out" effects:

$$\dot{A} = \frac{dA}{dt} = \gamma L^\lambda A^\phi$$

Key Research Findings & Answers

Q: Do OSS projects follow life cycles?

Yes. Developer engagement follows the classic S-curve lifecycle, peaking and eventually declining toward steady-state maintenance.

Q: Is growth endogenous?

Yes. Calibrated parameters (\(\lambda > 0, \phi < 0\)) show that initial developer expansion accelerates innovation, but code base size eventually leads to saturation ("fishing out").

Q: Are early life cycle forecasts stable?

Extremely. Fitting the model on only the first 75% of a project's lifetime yields almost identical trajectory forecasts compared to full-sample calibrations.

Q: What defines project maturation?

Maturation is defined when active developer engagement drops below 0.5 developer-months/month, leaving a core maintenance baseline.
